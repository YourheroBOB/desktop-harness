# 對照台灣個資法之缺口分析與建議（COMP-1～COMP-10）

> 對照基準：中華民國《個人資料保護法》（2015 修正施行版）之一般要求，含 §6 特種個資、§8 告知義務、§11 保存期限、§12 洩漏通知、§19 合法蒐集要件、§20 利用限制，以及《非公務機關個人資料檔案安全維護計畫處理辦法》之安全維護措施（含保存期限、稽核紀錄、事件處理）。**本對照為一般性工程盤點，非法律意見。**

## 0. 適用前提（BOB 需先決策）

個資法規範「非公務機關（含自然人為營業目的）」蒐集/處理/利用個資的行為。desktop-harness 作為**工具**並不當然適用；適用與否取決於**使用者以它執行的活動**：

- 個人非營業使用 → 原則上不適用（個資法 §51 自然人單純個人活動排除）。
- 律師/事務所/任何營業活動中用它驅動 agent 處理含當事人資料的畫面 → **適用**，且律師執業另有律師法/律師倫理的保密義務疊加。

本文件以「**適用**」為保守前提作盤點。若 BOB 判定僅個人使用，缺口優先級可整體降一級，但 D4/D8 跨境流向與工具本身的保存空白仍建議處理（成本低、風險實在）。

## 1. 缺口總表

| ID | 個資法對照 | 缺口 | 嚴重度 | 建議（最保守方向） |
|----|-----------|------|--------|---------------------|
| COMP-1 | §8 告知義務、§19 特定目的、§20 利用限制 | **stdout／截圖內容跨境進 LLM 服務商，無告知、無目的限定、無最小化設計**；文件僅宣稱「核心零網路」，未處理 agent host 外傳這個主流向 | **高** | (a) README/SECURITY 增補「agent 模式下螢幕內容會進入 LLM 服務商」的明確告知；(b) SKILL.md 增列最小化政策（不原樣回傳個資、敏感欄位遮罩後再回傳）；(c) 評估敏感 app 清單外擴至訊息/郵件/網銀類的「截圖需確認」選項 |
| COMP-2 | §11 保存期限、安全維護辦法保存期限 | 截圖無期限無刪除（PERC-3）；`capture.TMP` 不可覆寫 | 高 | 依 fmb-perf PERC-3 sweep + 保存期限 + `DH_CAPTURE_DIR` 覆寫（詳 retention-and-deletion.md） |
| COMP-3 | 安全維護辦法（紀錄保存與管理） | audit log 無輪替、無保留政策、寫入失敗靜默（TR-4/OBS-2） | 高 | 輪替 + 保留 N 份 + 失敗可見警告；文件寫明保留期 |
| COMP-4 | 安全維護辦法（去識別化） | audit 可能記錄 click 目標文字／app 名等準個資欄位（待確認 helpers 端） | 中–高 | 確認後遮罩（長度/hash 化）；`set_field` 不記值的既有原則推廣到所有 detail |
| COMP-5 | §11 當事人刪除權、安全維護辦法（當事人請求） | 無任何刪除機制、無 purge 指令、無當事人請求處理流程；解除安裝不清理 | 高 | `purge` 子命令 + uninstall 清單 + 文件化「無法逐當事人刪除，需人工」事實 |
| COMP-6 | §19/§20 跨境利用、委託處理 | voice 實驗路徑把語音+文字稿即時送境外（api.x.ai），無告知/同意設計；transcript 印到 stdout | 中（實驗性、預設關閉） | VOICE.md/README 明確標示跨境傳輸性質；transcript 遮罩選項；業務使用時列入委託處理評估 |
| COMP-7 | 供應鏈／安全維護（程序面） | 無 lockfile、無授權/漏洞掃描重現基準；voice 相依未進 metadata | 中 | lockfile（uv/pip-tools）+ `[project.optional-dependencies] voice` + release checklist 增「產出相依授權清單」 |
| COMP-8 | §12 洩漏事件通知義務 | 無任何資安/個資事件應變流程文件（SECURITY.md 僅有回報漏洞的 GitHub issue 路徑，且未涵蓋「通知當事人」） | 中 | SECURITY.md 增補事件處理段：偵測→評估→通知當事人（適當方式）→記錄；工具層至少提供 audit 佐證 |
| COMP-9 | §6 特種個人資料（病歷/醫療/基因/性生活/健康檢查/犯罪前科） | 截圖與 AX 讀取無任何內容過濾；特種個資可原樣落地並外傳 | 高（業務情境下） | 最保守：業務使用時以 SOP 禁止對含特種個資畫面截圖/外傳；中期：敏感清單 + 截圖確認閘門；自動內容偵測超出本工具範圍（需 BOB 決策） |
| COMP-10 | 委託處理（agent host / xAI 為受託方或第三方） | 使用 LLM 服務處理個資前的委託契約/資料處理條款評估，完全未發生於文件層 | 高（決策層） | BOB 決策：是否允許含個資內容進 agent host；若允，需確認服務商資料處理條款（訓練用途/保留期/刪除權），並在安全維護計畫中記錄 |

## 2. 依台灣個資法義務的快速對照

| 義務 | 現況 | 主要缺口 |
|------|------|----------|
| 合法蒐集要件（§19） | 視使用情境；工具層無輔助機制 | COMP-1、COMP-9 |
| 告知義務（§8） | 無任何告知文本 | COMP-1、COMP-6 |
| 特種個資限制（§6） | 無內容過濾 | COMP-9 |
| 保存期限與刪除（§11） | 全系統無 | COMP-2、COMP-3、COMP-5 |
| 安全維護措施（§27＋辦法） | 部分：權限 gate、audit（有缺陷）、token 0600；無保存期管理、無事件流程 | COMP-3、COMP-4、COMP-8 |
| 洩漏通知（§12） | 無 | COMP-8 |
| 當事人權利（查詢/更正/停止/刪除） | 無對應機制 | COMP-5 |

## 3. 建議處理順序（工程視角）

```
短期（低成本、高風險消除）：
  COMP-3 audit 輪替＋失敗警告（fmb-perf 已有方案）
  COMP-2 截圖 sweep＋保存期限
  COMP-5 purge 子命令
  COMP-1a/6 告知文本（README/SECURITY/VOICE 各一段）
中期：
  COMP-4 click_text audit 欄位遮罩（先確認 helpers 端實況）
  COMP-7 lockfile + voice extras
  COMP-8 SECURITY.md 事件處理段
決策層（BOB）：
  COMP-10 是否允許個資進 agent host（牽動 COMP-1 全部措施強度）
  COMP-9 特種個資 SOP
  §51 適用前提（個人 vs 營業使用）
```

## 4. 明確不做的事

- 不在 repo 寫入任何真實個資、案件資料、憑證（本目錄所有內容皆為虛構示例）。
- 不於本盤點修改任何原始碼或既有文件。
- 不宣稱本文件為法律意見或合規認證。
