# desktop-harness STRIDE 威脅模型

> **分析基準：**desktop-harness 0.4.2，以本次任務提供之檔案內容為準。  
> **分析範圍：**本機 CLI、任意 Python 執行入口、常駐 daemon、AX／截圖／HID 控制、代理工作區、稽核記錄、語音工具鏈、安裝與更新檢查。  
> **文件定位：**本文件專注跨元件的 STRIDE 威脅、攻擊路徑、現有控制缺口及程式碼層修補優先序。`docs/fmb-security/` 既有操作規範、憑證管理與安全建議不在此重複；本文件僅在描述威脅鏈時引用必要控制。

## 1. 執行摘要

desktop-harness 的核心能力是讓代理程式取得真實 macOS 的 Accessibility、螢幕擷取與輸入控制權。這不是一般讀寫工具，而是接近「以使用者身分操作整台桌面」的高權威介面。

目前最重要的安全結論如下：

1. **任意 Python 執行與常駐 daemon 是最高風險核心。** CLI 與 daemon 都接受任意程式碼；daemon 會在具備桌面控制能力的程序中執行該程式碼，且跨請求共用同一個 Python namespace。
2. **目前的同意機制主要是代理提示詞，不是執行期強制控制。** 送出、發布、購買、刪除、變更安全設定等高風險行為，仍可能由代理或語音模型直接觸發。
3. **AX 與截圖是雙向資料邊界。** UI 內容不僅可能被讀取，也可能含敏感資料；而 UI 文字本身又可形成間接提示注入，反向操縱代理。
4. **常駐 daemon 的隔離與可用性不足。** 驗證權杖可阻擋其他使用者，卻無法區分同一 macOS 使用者底下的不同程序；daemon 又是循序處理且沒有請求大小、執行期限或取消機制。
5. **稽核記錄可協助診斷，但不能提供不可否證性。** 寫入失敗會被忽略，記錄沒有交易識別、核准關聯或防竄改設計，任意程式碼路徑也不會形成完整交易軌跡。
6. **語音鏈把遠端模型回覆提升成桌面操作指令。** 現有工具雖未直接提供付款或刪除功能，但「輸入文字、快捷鍵、座標點擊」足以構成高權限的通用操作能力。

### 1.1 最高優先風險摘要

| 優先序 | 主題 | 核心風險 | 建議方向 |
|---|---|---|---|
| P0 | daemon 權限與請求隔離 | 任意程式碼在具桌面能力的常駐程序中執行，並可污染後續請求 | 拆分工具型 daemon 與明確啟用的 raw-exec daemon；每請求使用乾淨 namespace |
| P0 | 高風險操作的程式碼強制核准 | 代理提示詞可被忽略，語音模型亦可直接呼叫通用工具 | 建立與目標、動作及一次性核准綁定的執行期 gate |
| P0 | AX／截圖資料最小化 | 敏感 UI 可能被讀取、落地或傳至外部服務 | 私有權限、限期保存、明確範圍、欄位遮蔽與外部傳輸同意 |
| P0 | daemon 資源與競態控制 | 單一長時間請求可阻住整個 daemon；啟動與停止存在競態 | 請求期限、大小限制、隔離 worker、單一實例鎖 |
| P1 | 目標綁定與重驗證 | 檢查後焦點或 UI 改變，可能作用到錯誤目標 | 將 PID、bundle、角色、標籤與座標綁定後再動作 |
| P1 | 代理工作區與供應鏈 | 可編輯程式碼、skill 或未固定版本可跨工作階段持續影響行為 | 工作區簽核／隔離、依賴固定與校驗 |
| P1 | 可信稽核 | 事件可遺失、可修改，且無法關聯核准 | 結構化交易紀錄、可靠寫入與完整性保護 |

## 2. 方法、假設與風險尺度

### 2.1 方法

本模型依下列步驟建立：

1. 盤點資產、執行元件與外部參與者。
2. 定義信任邊界及跨邊界資料流。
3. 依 STRIDE 分析可直接操作、間接提示注入、程序隔離及供應鏈情境。
4. 評估可能性與影響。
5. 對照程式碼中可觀察到的控制，辨識控制的有效範圍與缺口。
6. 以可驗證的修補條件排列優先序。

### 2.2 基本假設

- desktop-harness 與代理程式通常以同一個 macOS 使用者身分執行。
- 代理收到的任務、畫面文字、網頁內容、文件內容及語音輸入均視為**不可信輸入**。
- 同一使用者底下的其他程序可能遭入侵；daemon 的檔案權限不能被視為同 UID 程序間的隔離。
- macOS Accessibility 與 Screen Recording 權限一旦授予，實際能力接近完整桌面操作。
- 語音鏈的遠端服務、回應模型及工具呼叫均視為跨組織信任邊界。
- 截圖與 AX 輸出可能包含機密、個人或業務資料，因此需最小化。
- 代理工作區、skill、Python 套件及 daemon 程式碼均視為可被供應鏈或提示注入影響的程式碼。

### 2.3 可能性

| 等級 | 定義 |
|---|---|
| 高 | 一般使用情境即可遇到，或只需誘導代理遵循惡意 UI／文件內容 |
| 中 | 需要惡意套件、同 UID 程式碼執行能力、錯誤設定或特定部署條件 |
| 低 | 需要上游供應鏈遭入侵、罕見環境組合或額外弱點 |

### 2.4 影響

| 等級 | 定義 |
|---|---|
| 嚴重 | 憑證或敏感資料外洩、未授權交易、廣泛桌面控制，或無法可靠追蹤重大操作 |
| 高 | 未授權但可回復的桌面操作、敏感內容揭露、重要服務中斷 |
| 中 | 單一應用或工作階段受影響、可由使用者復原 |
| 低 | 輕微資訊洩漏、短暫可用性問題或有限資料毀損 |

## 4. 參與者

| 參與者 | 能力與動機 |
|---|---|
| 正常使用者 | 明確授權桌面操作，但未必每次都知道代理的內部行為 |
| 正常代理程式 | 接收任務並產生 CLI 程式碼；可能因提示注入、模型錯誤或工具誤用而偏離原意 |
| 惡意或遭入侵的代理程式 | 可產生任意 CLI 程式碼，並可能嘗試讀取環境、竄改狀態或擴大操作範圍 |
| 畫面或文件中的攻擊者 | 透過 AX 標籤、網頁、PDF、郵件或訊息內容植入間接提示注入 |
| 同一 UID 的惡意程式 | 可讀取該使用者檔案及 daemon 認證能力，並可能利用 daemon 取得額外桌面能力 |
| 其他本機使用者 | 在共享主機上可能嘗試讀取暫存畫面、稽核記錄或連線 daemon |
| 遠端語音服務或模型供應者 | 接收語音／文字與工具結果，並回傳工具呼叫；可能遭入侵或遭誘導發出高權限呼叫 |
| 套件或發行來源攻擊者 | 透過未固定依賴、安裝 script 或 skill 更新植入程式碼／行為 |
| 誤操作或競態 | 不具惡意，但可因焦點改變、應用程式名稱相似或逾時而作用到錯誤目標 |

## 5. 元件與信任邊界

### 5.1 主要元件

| 元件 | 職責 | 信任特性 |
|---|---|---|
| 使用者／代理提示 | 產生任務、自然語言指令與 CLI 程式碼 | 不可信輸入，即使由正常使用者發起也可能遭注入 |
| CLI `run.py` | 讀取 stdin、檔案或命令列程式碼，選擇本機或 daemon 執行 | 高權威入口；不應將 shell 能力誤認為已沙箱化 |
| 本機執行命名空間 | 暴露 helper，並以 Python `exec` 執行程式碼 | 與呼叫程序相同使用者權限 |
| 常駐 daemon | 接受 NDJSON 請求、保存 namespace、執行 raw code | 高權威、長壽命、跨請求共享狀態 |
| AX／視窗模組 | 讀取應用程式、視窗與 Accessibility 結構 | 跨越「不可信應用內容 → 代理」邊界 |
| 截圖模組 | 擷取指定視窗或整個顯示器並寫入 PNG | 跨越「OS 畫面 → 檔案／代理」邊界 |
| 輸入模組 | 發送全域滑鼠與鍵盤事件 | 跨越「代理 → 應用程式」邊界 |
| 代理工作區 | 自動載入任務專用 helper | 與代理相同信任等級，但可跨工作階段延續影響 |
| 稽核記錄 | 記錄部分 helper 事件 | 診斷用途；尚未形成防竄改交易帳本 |
| 語音工作階段 | 連接遠端服務、接收工具呼叫並回傳結果 | 明確的外部資料與命令邊界 |
| 安裝器／更新檢查 | 安裝依賴、寫入 PATH shim 與 skill；查詢上游版本 | 發行與供應鏈邊界 |

### 5.2 信任邊界

| ID | 邊界 | 跨越方向 | 理想控制 | 現況摘要 |
|---|---|---|---|---|
| TB-01 | 使用者／任務 → 代理 | 外部文字、文件、網頁、UI 內容進入模型上下文 | 內容分級、資料流標記、不可信指令處理 | 主要依賴代理遵循提示詞，沒有強制資料標記 |
| TB-02 | 代理 → CLI | 任意 Python 程式碼進入執行環境 | 最小能力、核准、隔離 | CLI 刻意允許任意程式碼，與使用者權限相同 |
| TB-03 | CLI → daemon | 本機 socket 請求與認證能力 | 每呼叫者認證、請求隔離、資源限制 | 有隨機權杖與 0600 檔案／socket；同一 UID 仍共用權威，且無資源期限 |
| TB-04 | harness → macOS | AX、截圖、HID、應用程式啟動 | 最小 TCC 權限、目標綁定 | 取得 TCC 後可操作真實桌面；多數檢查只覆蓋 helper 路徑 |
| TB-05 | 應用程式／網頁 → AX／截圖 → 代理 | UI 內容回流為模型輸入 | 欄位遮蔽、內容不可信標記 | 尚無一般化遮蔽或提示注入防線 |
| TB-06 | 使用者檔案 → harness | 設定、工作區、skill、套件載入 | 擁有者／完整性驗證、隔離載入 | 工作區可編輯且會自動載入；skill 由安裝器寫入 |
| TB-07 | 語音工作階段 ↔ 遠端服務 | 文字／語音外送，模型回傳工具呼叫 | 明確 opt-in、資料最小化、工具授權 | 使用加密連線，但資料外送與工具呼叫仍由程式流程直接驅動 |
| TB-08 | 代理／遠端回覆 → 高風險 UI | 一般輸入、快捷鍵與點擊形成實際操作 | 目標綁定、一次性核准、危險動作分類 | 同意主要存在於 skill 與模型指示，沒有執行期 gate |
| TB-09 | 套件／發行來源 → 使用者環境 | 安裝程式碼與套件進入本機 | 版本固定、雜湊、簽章、來源驗證 | 依賴未固定版本；安裝器直接下載並寫入使用者環境 |
| TB-10 | harness → 遠端版本資訊 | 讀取上游版本中繼資料 | 來源綁定、簽章驗證 | 僅讀取且不自動更新，但查詢端點與目前 clone 的來源可能不一致 |

> **重要邊界事實：**多數部署只有一個 macOS 使用者。同一使用者下的代理、daemon、CLI、skill 與其他本機程式通常共享同一 OS 身分。因此「檔案只有擁有者可讀」不等於「能區分同一使用者內的惡意程序」。

## 6. 資料流

```text
[使用者／代理任務／不可信 UI 內容]
                 |
                 | DF-01：任務、指令、任意 Python
                 v
            [CLI run.py]
              |       \
              |        \ DF-02：本機 exec
              |         v
              |      [OS 使用者權限]
              |
              | DF-03：本機 socket + 認證能力
              v
       [常駐 daemon／共享 namespace]
              |
              +---- DF-04：AX 查詢 ----> [應用程式]
              |          |
              |          | DF-05：AX 標籤／值
              |          v
              |       [代理／模型]
              |
              +---- DF-06：畫面擷取 --> [暫存 PNG] --> [代理／模型]
              |
              +---- DF-07：HID 事件 ---> [目前焦點應用程式]
              |
              +---- DF-08：helper 事件 -> [本機稽核記錄]
              |
              +---- DF-09：工作區程式碼 -> [自動載入命名空間]

[語音輸入／文字] --DF-10--> [遠端語音服務]
                              |
                              | DF-11：工具呼叫
                              v
                         [語音工具執行器]
                              |
                              | DF-12：AX 結果／工具輸出
                              v
                         [遠端語音服務]

[發行／套件來源] --DF-13--> [安裝器／本機環境]
[本機 harness]      --DF-14--> [上游版本中繼資料服務]
```

| DF | 資料流 | 資料／控制內容 | 主要風險 |
|---|---|---|---|
| DF-01 | 任務或代理 → CLI | 自然語言、程式碼、參數 | 提示注入、被誘導執行任意程式碼 |
| DF-02 | CLI → 本機 Python | 任意 Python、helper namespace | 取得檔案、網路、程序與桌面能力 |
| DF-03 | CLI → daemon | 操作、程式碼、認證能力 | 權杖被同 UID 程序取得、跨請求污染 |
| DF-04 | daemon → helper／OS | AX、截圖、HID、應用程式操作 | 常駐高權威程序被誤用或劫持 |
| DF-05 | 應用程式 → AX → 代理 | 標籤、標題、欄位值、視窗資訊 | 敏感資料外洩、間接提示注入 |
| DF-06 | OS → 畫面檔案 → 代理 | PNG 畫面內容 | 跨使用者讀取、殘留、外送 |
| DF-07 | harness → 應用程式 | 滑鼠與鍵盤事件 | 作用到錯誤目標、輸入外洩、誤操作 |
| DF-08 | helper → 稽核記錄 | 事件、應用程式、視窗、檔案路徑 | 資料最小化不足、不可竄改性不足 |
| DF-09 | 工作區 → 執行環境 | 可編輯 helper 程式碼 | 跨工作階段持續執行惡意程式 |
| DF-10 | 語音輸入 → 遠端服務 | 文字或未來麥克風音訊 | 隱私外送、服務端遭入侵 |
| DF-11 | 遠端模型 → 工具執行器 | 工具名稱與參數 | 遠端回覆取得桌面命令權 |
| DF-12 | 工具執行器 → 遠端服務 | AX 標籤與工具結果 | 螢幕語意資料外送 |
| DF-13 | 套件來源 → 安裝環境 | 依賴、建置工具、skill | 供應鏈劫持、持續性行為植入 |
| DF-14 | harness → 上游資訊服務 | 版本中繼資料 | 錯誤來源、供應鏈混淆；目前不自動安裝 |

## 7. STRIDE 威脅情境

### 7.1 Spoofing（身分冒充）

| ID | 威脅情境與攻擊路徑 | 資產 | L | I | 現有緩解 | 主要缺口 |
|---|---|---|---|---|---|---|
| S-01 | 惡意或遭入侵的代理以合法 CLI 介面提交任意程式碼；系統只看到正常使用者程序。 | A-01、A-04、A-09 | 中 | 嚴重 | OS 使用者權限、daemon 認證 | 沒有呼叫者身分與真人發起因素的強關聯；認證只證明「知道共用權杖」 |
| S-02 | 同一 UID 的惡意程序讀取認證能力檔並直接連線 daemon，冒充正常代理。 | A-01、A-05、A-06 | 中 | 嚴重 | 認證能力隨機產生；token 與 socket 檔明確設為 0600 | 同 UID 程序仍可讀取檔案；無法阻止其借用 daemon 的桌面能力 |
| S-03 | 以相似應用程式名稱、視窗標題或非同步焦點變化，使控制目標被錯認為另一個應用程式。 | A-01、A-04 | 中 | 高 | 應用程式查找採 exact-first、bundle ID 及 PID | 視窗選擇仍有 owner／title 子字串比對；檢查與執行未原子綁定 |
| S-04 | 在語音模式啟用後，未驗證的說話者或合成語音被誤認為使用者本人，進而形成「已確認」印象。 | A-07、A-12 | 中 | 高 | 模型提示要求語音確認 | 沒有說話者驗證、挑戰式核准或畫面確認；目前麥克風路徑仍屬 scaffold |

### 7.2 Tampering（竄改）

| ID | 威脅情境與攻擊路徑 | 資產 | L | I | 現有緩解 | 主要缺口 |
|---|---|---|---|---|---|---|

## 9. 具代表性攻擊鏈

### AC-01：畫面內容 → 提示注入 → 未授權操作

1. 代理讀取包含惡意指示的網頁或應用程式 AX 標籤。
2. 惡意內容被當成高優先級任務或「使用者已核准」的敘述。
3. 代理呼叫輸入、快捷鍵或點擊 helper。
4. 操作在目前焦點的敏感應用程式完成。

**現有控制：**高風險詢問規則、敏感 app 阻擋、事後 `verify`。  
**失效原因：**畫面內容與使用者命令沒有不可信邊界；沒有執行期、與目標綁定的核准；一般瀏覽器不在敏感 app 清單。

### AC-02：同 UID 程式 → 認證能力 → daemon confused deputy

1. 遭入侵的同 UID 程式讀取 daemon 認證能力。
2. 程式連線常駐 daemon。
3. 送出 raw-exec 請求。
4. daemon 以其桌面能力執行請求，或污染共享 namespace 供後續使用。

**現有控制：**0600 權杖與 socket、隨機權杖。  
**失效原因：**同 UID 沒有程序隔離；raw exec 能力可跨請求延續。

### AC-03：代理工作區污染 → 常駐 daemon 持續影響

1. 代理或供應鏈修改自動載入的工作區 helper。
2. 新 daemon 或工作階段載入該程式碼。
3. helper 改寫其他 helper、擷取資料或改變安全檢查。
4. 後續與該 daemon 相關的代理工作持續受影響。

**現有控制：**工作區由使用者擁有；skill 與套件可人工檢視。  
**失效原因：**沒有簽核、hash、來源證明或工作階段隔離。

### AC-04：語音模型 → 通用工具 → 不可逆操作

1. 遠端模型依語音或誘導內容產生工具呼叫。
2. 呼叫通過名稱式工具 allowlist。
3. 通用快捷鍵或輸入動作在實際焦點應用程式執行。
4. 沒有與該呼叫參數綁定的可驗證核准。

**現有控制：**語音 session instructions、有限 schema。  
**失效原因：**allowlist 只限制「有哪些 helper」，沒有限制「helper 可做哪些高風險操作」。

### AC-05：截圖落地 → 其他本機使用者讀取

1. 代理對一般或敏感前景執行截圖。
2. PNG 寫入暫存目錄，權限未明確限定為擁有者。
3. 同一共享主機上的其他使用者在檔案存在期間取得畫面。

**現有控制：**唯一檔名、部分敏感 app 阻擋。  
**失效原因：**沒有明確 0700／0600、到期清除、內容分類與跨使用者隔離。

## 10. 修補優先順序

以下優先序以「降低可被利用的桌面權威與資料外洩」為準，不取代既有安全操作文件。

### P0：下一次對外使用前完成

| 項目 | 修補內容 | 對應威脅 | 可驗收條件 |
|---|---|---|---|
| P0-01：分離 daemon 權限模型 | 預設 daemon 僅提供 allowlist 工具 API；raw exec 必須由本機使用者明確啟用，且不得供語音鏈使用。每次請求使用全新 namespace，不得保留前次 helper 或名稱綁定。 | T-03、E-01、E-02、E-04 | 呼叫端無法在一般 daemon 路徑提交任意程式碼；前一請求修改 helper 不影響後一請求；語音工具只能呼叫已核准 API |

| P1-03：可信稽核與交易關聯 | 為高風險動作記錄 session、actor、target、核准 ID、事件與結果；寫入失敗需產生可見告警；對記錄加入完整性保護、輪替與保留期限。 | R-01、R-02、R-03 | 可由單一核准 ID 還原動作鏈；竄改或寫入失敗可被偵測；記錄不保存輸入內容等不必要敏感值 |
| P1-04：供應鏈固定 | 依賴與建置工具採可重現版本或 lockfile，安裝時驗證來源與完整性；skill 更新需顯示差異並取得確認。 | T-05 | 相同來源可重現安裝；未驗證版本或 skill 不會靜默進入代理環境 |
| P1-05：語音邊界收斂 | 將語音模式與一般 raw-exec daemon 分離；預設不回傳完整 AX 結果；建立明確的資料類型 allowlist；核准需由本地 UI 顯示實際目標與動作。 | I-04、E-04 | 語音工作階段無法取得 raw-exec 能力；遠端回傳資料符合 allowlist；核准畫面與實際呼叫一致 |
| P1-06：修正 dry-run 語意 | dry-run 不得讀取 AX、視窗或畫面；另設明確的唯讀診斷模式，並在輸出標示實際存取的資料。 | I-06 | 測試確認 dry-run 不呼叫 AX、截圖與 OS 輸入 API |

### P2：持續強化

| 項目 | 修補內容 | 對應威脅 | 可驗收條件 |
|---|---|---|---|
| P2-01：更新來源綁定 | 查詢目前 clone 的受信任來源，不使用與部署來源無關的固定上游；即使只顯示版本，也驗證來源身分。 | TB-10、DF-14 | 不同 clone 不會把另一個上游誤認為自己的更新來源 |
| P2-02：提示注入測試集 | 建立惡意 AX 標籤、視窗標題、文件文字與工具回應測試案例，驗證不能自行形成核准或改寫任務。 | T-01 | 所有案例均無法跨過高風險核准 gate |
| P2-03：模糊化與重送模糊測試 | 測試相似 app 名稱、焦點競態、重複使用核准、截圖路徑及請求大小邊界。 | S-03、T-02、R-03、P0-04 | 邊界案例 fail closed，且不依賴正式網路服務 |

## 11. 驗證原則

後續修補的測試應遵守：

- 不連線任何正式語音、更新或第三方服務；遠端流程使用本地 mock。
- 所有畫面、token 與稽核測試檔案使用暫存目錄，並驗證結束後的權限與清除行為。
- 測試不得使用真實帳號、客戶資料、通訊內容或案件資料。
- 測試必須包含同 UID 模擬、HA 模式、focus 競態、提示注入、核准重放與 daemon 資源飽和情境。
- macOS 專屬的 TCC 行為需要人工確認者，應列為獨立驗收項，不可只用一般 Linux CI 結果替代。

## 12. 待 BOB 裁示事項（採保守預設）

1. **是否保留 raw-exec daemon：**保守預設為保留但改為明確啟用，預設 daemon 僅提供 allowlist API；語音鏈永遠不可取得 raw exec。
2. **是否支援共享、多使用者 Mac：**保守預設為不支援；安裝或啟用時主動拒絕不明共享環境，並以專用 macOS 使用者作為高權限部署前提。
3. **語音是否允許回傳 AX 結果：**保守預設為只回傳完成任务所需的最小結構化結果，不回傳完整欄位值；完整標籤需另外 opt-in。
4. **是否允許整個顯示器截圖：**保守預設為不允許隱式整屏擷取；只能由使用者明確要求，且每次要求都套用與敏感前景相同的 gate。
5. **高風險動作的核准方式：**保守預設為本機一次性核准物件，綁定目標與參數；不得只接受模型自行產生的「使用者已同意」文字。
6. **稽核保留期限：**保守預設為短週期、只記錄 metadata 與核准關聯，不保存輸入內容或完整畫面。

## 13. 結論

desktop-harness 的主要風險不是單一 helper 的按鈕錯誤，而是「不可信內容可進入代理上下文」與「代理可取得真實桌面高權威」之間缺少強制技術邊界。現有敏感 app 清單、提示詞同意、0600 daemon 檔案與稽核記錄能降低日常誤用，但都不是隔離或不可否證性控制。

優先順序應聚焦於：先限制常駐 daemon 的一般權限與跨請求狀態，再以目標綁定的一次性核准保護高風險操作，同時將 AX／截圖視為敏感資料流。只有完成這些控制，才能把產品定位由「高權威本機工具」提升為「可合理交付給代理使用的桌面控制介面」。
